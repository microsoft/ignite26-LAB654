# Mock environment

Synthetic tenant data for testing the LAB654 scenarios (legal, finance, productivity, engineering and the custom MCP expense track). The tenant is provisioned with [COEP schemas](https://coep.microsoft.com/schema/portal).

## Layout

| Path | Purpose |
|------|---------|
| `_schemas/` | The latest COEP schemas, rules and examples for every type, laid out as `<Category>/<type>/`. `manifest.json` records the version and fetch date. |
| `_naming/` | Local only, not committed (in `.gitignore`). The CELA source files for names; see [Names](#names). |
| `Connectors_Ignite_EMP/` | The COEP package for the virtual tenant: `config.json` plus a `<type>.config.json` for each Microsoft 365 type that has data (currently users, emails, chats, events, teams, channels, channel messages and replies, and online meetings). Meeting transcripts are in `transcripts/`. Connector types use a `<type>/` folder of `<type>_<scenario>.jsonl` files, one item per line (currently `confluence/` and `customconnectors/`), as COEP's Connector Entity Guide requires. |
| `Connectors_Ignite_EMP/files/` | Enterprise documents for `files.config.json`. Created only when a scenario puts files in the tenant. The legal scenario has none. |
| `mock_mcp_servers/` | Mock MCP servers for third-party connectors, each with a `seed_files/` folder. See [its README](mock_mcp_servers/README.md). |
| `mock_plugins/` | Microsoft 365 app packages for the connectors, pointed at the mock MCP servers. See [its README](mock_plugins/README.md). |
| `tools/` | The generator, validator and schema refresh scripts. |
| `tools/scenarios/` | One module per scenario holding its tenant seed data, plus `<scenario>_content/` for source content such as email bodies. |

The package files are generated, so make changes in `tools/scenarios/<scenario>.py` and rebuild rather than editing the JSON directly.

## Names

Company names, domains and people names follow Microsoft CELA's fictitious-names guidance: [Trademarks: fictitious names](https://microsoft.sharepoint.com/sites/CELAWeb-Copyrights-Trademarks-And-Patents/sitepages/trademarks-fictitious-names.aspx) (internal).

- **Companies and domains:** from CELA's *Approved Fictitious Company Names and Domain Names* list (Feb 2026, 38 companies). The lab uses 10 of them: Zava, Trey Research, Lakeshore Retail, Boulder Innovations, Wide World Importers, Tailspin Toys, Lucerne Publishing, Nod Publishers, Fabrikam, Inc. and Adatum Corporation. Names and domains are used exactly as listed.
- **People:** 50 names generated by CELA's Fictitious Names Finder (request `FNF-2026-11-01-01366-0340`: random mix of languages, any gender). The lab uses 26 of them, matched to each person's role and the pronouns in the scenarios.
- **Email addresses:** first name only, as CELA requires (for example `zoe@zava-online.com`). Tenant aliases follow the same rule (`emil`, `hemanti`, `luc`).
- **Exceptions:** the finance track analyses real public companies (NVIDIA, AMD and others), and the expense receipts come from real merchants (Alaska Airlines, The Westin Seattle and others). Both are on purpose.

The PDF and the CSV are internal, so they're kept locally in `_naming/` and not committed. To recreate the folder, download the PDF from the CELA page and request names there with the settings above.

## Build and validate

Requires Python 3.10 or later with `jsonschema` installed.

```powershell
pip install jsonschema
python infra/mock_environment/tools/build_tenant.py
python infra/mock_environment/tools/validate_package.py
```

The validator checks the package against `_schemas` (JSON Schema 2020-12). It also applies the main COEP cross-file rules:

- user and license references
- that referenced files exist and match `FileName`
- shared links and placeholders
- email reply chains
- chat membership
- that timestamps are before `--as-of` (the planned provisioning time; defaults to now)

COEP rejects timestamps in the future. The legal story is pinned to a Monday lab date (`LAB_DATE` in `tools/scenarios/legal/__init__.py`, currently Mon Oct 12, 2026). The email is 14 days earlier, the group chat 6 days earlier, and the trigger message is at 8:07 AM ET on the lab date. The kit's original lab date was Mon Nov 9, 2026; every date in the seed data, the iManage documents and the scenario docs was moved back 28 days so everything is in the past, keeping weekdays and the contract's anniversary and payment schedule intact. To move the story again (for example, closer to the event), run:

```powershell
python infra/mock_environment/tools/scenarios/legal/redate.py --lab-date 2026-11-02
python infra/mock_environment/tools/build_tenant.py
```

## Refresh the schemas

```powershell
$env:COEP_TOKEN = "<bearer token from the COEP portal>"
python infra/mock_environment/tools/refresh_schemas.py
```

To get a token, sign in to the portal and copy the `Authorization` bearer value from any `/schema/api/v1` request in the browser dev tools. After refreshing, run the validator again.

To add a scenario, create a module or package under `tools/scenarios/` that exposes `users()`, `emails()`, `chats()`, `events()` and `files()`, and optionally the other hooks listed in `build_tenant.py` (`teams()`, `channels()`, `onlinemeetings()`, `transcripts()`, `confluencepages()`, `customconnectors()`, `build_documents(files_dir)` and others). Then add it to `SCENARIOS` in `build_tenant.py`.

- One lab account plays every track. Emil Vanggaard at Zava (from the legal scenario) is the Copilot user everywhere; the other tracks reuse him instead of seeding their own driver. His profile stays "Associate General Counsel, Technology Transactions" in Legal, so the other tracks' prompts don't state a job title.

- Finance: the asset manager becomes the Zava Investment Office, which invests the insurer's reserves. Kristian is a Zava employee in Stamford with mailbox and Teams only.
- Finance: Kristian's trigger message is pinned to Fri Oct 9, 2026, 4:00 PM ET (`ASK_DATE` in `tools/scenarios/finance/__init__.py`). The investment committee isn't seeded as people or a meeting because the one-pager doesn't name its members or time.
- Productivity: the Lakeshore Retail people (Atul Manohar, Jahidi Juma, Nanami Nakayama) are tenant accounts so their email and meeting validate; Zoe Armstrong is at Zava. They have mailbox and Teams only. Salesforce data lives in the Test_Salesforce mock, not the tenant.

The pitch is Fri Nov 20, 2026, with busy blocks Nov 23-25 and out of office Nov 26-27, so "next week" slots look real during lab week. Test_Confluence pages are in the "Zava Sales" space.
- Engineering: Jira data (AUR-142, AUR-145, Sprint 24) lives in the Test_Jira mock. GitHub data (PR #287, Tama's changes-requested review and merged decoy PRs) lives in the Test_GitHub mock, where writes are kept per conversation. The older synced Test_GitHub connection is still in the tenant seed but the lab doesn't use it.
- Expense: Emil's Seattle trip runs Mon Oct 26 - Thu Oct 29, 2026. Receipt senders are tenant users whose display names are the merchant names, so the emails pass schema checks. Hannes Niemi (manager) and Ebere Ibeabuchi (Finance Operations) are the Zava users the expense mock routes to.
- All tracks except legal and finance: seeded evidence is dated on or before Fri Oct 30, 2026; anything still to come is on or after Fri Nov 20, 2026 (see [REVAMP_PLAN](../../docs/scenarios/REVAMP_PLAN.md)).
