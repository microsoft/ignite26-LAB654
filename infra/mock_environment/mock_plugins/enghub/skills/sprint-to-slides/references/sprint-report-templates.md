# Sprint Report Templates

Production-ready templates for Word reports and PowerPoint slides generated by the sprint-to-slides skill.

---

## Word Document Structure

### Template Overview
The Word report is a 4–6 page polished document suitable for distribution to executives, boards, and stakeholders. Use `python-docx` to generate programmatically, or provide this structure to a template-based Mail Merge workflow.

### Page 1: Title Page

```
HEADER:
[Company Logo] [4cm from top]

CENTERED TEXT:
Sprint {name}
{date range} (e.g., "April 1–12, 2026")

[double space]

{project_name} Team
{team_size} engineers

[footer, small text, gray]
Prepared by: {report_author}
Date: {report_date}
```

**Styling:**
- Font: Helvetica Neue, 14pt title, 11pt subtitle
- Colors: Black title, dark gray metadata
- Spacing: 1.5 line height, centered alignment
- Margins: 1 inch all sides

---

### Page 2: Executive Summary

**Section Header:** "Executive Summary" (Helvetica Neue, 12pt bold, all caps, with 1pt gray rule below)

**Content (prose):**
- 2–3 sentences on sprint goal and outcome
- 1 headline metric (e.g., "Completed 12 stories, 34 points, 86% of commitment")
- 1–2 key accomplishments (1 sentence each)
- Risk summary (1 line, if applicable)

**Example:**
```
Sprint 42 focused on delivery of the relational memory prototype and internal 
tooling improvements. The team completed 12 stories (34 points), achieving 86% 
of sprint commitment despite a mid-sprint blocker that was successfully 
mitigated in partnership with the platform team.

Key highlight: The relational memory API shipped on schedule, unlocking Phase 3 
roadmap and customer research planned for end of month.

Risk: 2 stories (5 points) carrying over due to scope expansion in payment 
validation; low impact to roadmap timeline.
```

**Styling:**
- Paragraph font: 11pt, 1.15 line height
- Margins: 0.75 inch left/right
- Spacing: 12pt between paragraphs

---

### Page 2 (Lower): Metrics at a Glance

**Mini-table (no borders, light gray header row):**

```
Metric                      Current     Trend       Target
Velocity (points)           34          +21%        32–35
Completion rate             86%         Stable      90%+
Carry-over points           5           0%          <10%
Bug ratio per story         0.33        Improved    <0.5
Blocker resolution rate     100%        Excellent   >90%
Team engagement (tickets)   5 members   Stable      Full team
```

**Styling:**
- Font: 10pt monospace (JetBrains Mono) for numbers, 11pt Helvetica for labels
- Header row: Light gray background (RGB 240, 240, 240), bold text
- Borders: None (clean, minimal look)
- Alignment: Right-aligned numbers, left-aligned labels

---

### Page 3: What We Accomplished

**Section Header:** "What We Accomplished"

**Subsection by epic or feature (11pt bold, dark gray):**

For each completed feature:
```
Feature: {feature_name}
Summary: {1–2 sentence description of what was built and why}
Stories: {count} | Points: {total} | Lead: {assignee_name}

Key metrics:
- Performance improvement: {e.g., "40% faster load time"}
- Customer impact: {e.g., "Enables Phase 3 research with 5+ enterprise accounts"}
- Technical achievement: {e.g., "Refactored memory layer for encryption compliance"}
```

**Team highlights (call-out box, light blue background, 0.5pt border):**
```
Team Highlight:
Alice led the relational memory API design and implementation, working closely 
with the platform team to resolve rate-limiting constraints. Her partnership 
model is now a template for future cross-team integrations.
```

**Styling:**
- Feature summary: 11pt, bold, dark gray
- Description text: 10pt, regular, black
- Call-out boxes: Light blue (RGB 235, 245, 255), 0.5pt gray border, 10pt italic
- Spacing: 12pt between features, 6pt between metrics

---

### Page 4: Blockers, Risks & Learnings

**Section Header:** "Blockers, Risks & Learnings"

**Subsection: Blockers Encountered & Resolved**

```
Blocker: {title}
Description: {what blocked progress}
Resolution: {how it was resolved, who helped}
Timeline: {when encountered, when resolved}
Learning: {what we'll do differently next sprint}

Status: [RESOLVED] | Impact: [MITIGATED]
```

**Subsection: Risks for Next Sprint**

```
Risk: {title}
Description: {potential impact}
Probability: [HIGH|MEDIUM|LOW]
Mitigation: {action plan}
Owner: {name}
```

**Subsection: Process Observations**

```
Positive observations:
- {Observation 1}
- {Observation 2}

Areas for improvement:
- {Observation 1}
- {Observation 2}
```

**Styling:**
- Blocker/Risk headers: 11pt bold, dark gray
- Status tags: Bold, color-coded (green for RESOLVED, orange for IN PROGRESS, red for OPEN)
- Text: 10pt, regular
- Spacing: 12pt between items

---

### Page 5: Next Sprint Goals

**Section Header:** "Next Sprint Goals & Carry-Over"

**Carry-Over Items (table):**

```
Story Key    Title                         Points    Reason
ENGHUB-234   Payment validation refactor   3         Scope expanded mid-sprint
ENGHUB-235   Auth flow documentation       2         Discovery incomplete
```

**Next Sprint Focus (prose + bullet points):**

```
Next sprint (April 15–26) will focus on:
- Completing carry-over payment validation refactor (blocks Phase 1 merge)
- Beginning integration testing for relational memory + core APIs
- Dependency sync with product team on customer research schedule
- Tech debt: Upgrade test suite to latest Jest version

Capacity planning:
- Target velocity: 32–35 points
- Planned work: Carry-over (5 points) + new features (27–30 points)
- Reserve: 1–2 points for critical bugs or escalations
```

**Styling:**
- Prose: 11pt, 1.15 line height
- Bullets: 10pt, 0.5 inch indentation
- Table: 10pt monospace, light gray header row
- Spacing: 12pt between sections

---

### Page 6: Appendix (as needed)

**Full Story List**

```
Key         Status    Points  Assignee    Title

ENGHUB-202  Done      5       Bob         UI session persistence
ENGHUB-203  Done      3       Carol       Recovery flow UX
ENGHUB-204  Done      8       Dave        Test suite & integration

```

**Styling:**
- Monospace table (10pt JetBrains Mono), 0.5pt borders
- Zebra striping (alternating light gray/white rows) for readability
- Left-aligned text, right-aligned points
- Page break before appendix if needed

## PowerPoint Slide Templates

### General Slide Design System

**Master slide layout (all audiences):**
- Background: White (or light gray for dark mode variant)
- Font: Helvetica Neue (headers), system sans-serif (body)
- Header: Project/sprint name in top-left corner (8pt, gray)
- Footer: Slide number and date (8pt, gray, right-aligned)
- Margins: 0.5 inch all sides
- Accent color: Brand blue (use EngHub Design System blue if applicable)

**Typography:**
- Slide title: 32pt bold, dark gray or black
- Bullet points: 16pt, regular, dark gray
- Numbers/metrics: 24pt bold, brand blue
- Speaker notes: 11pt, regular, full prose (not bullet points)

### Executive Audience: 8-Slide Deck

**SLIDE 1: Title Slide**
- Title: "{Sprint Name}" (32pt)
- Subtitle: "{Date Range} | {Team Name}"
- Visual: [Company logo, top-right corner]
- Speaker notes: "Good morning. This is a review of Sprint 42, our relational memory sprint, which ran from April 1st through April 12th. [Pause]. I want to walk you through what we shipped, the metrics that show we're on track, and one critical partnership moment that de-risked Phase 3 of the roadmap."

**SLIDE 2: Sprint at a Glance**
- 3 metrics, hero format (24pt bold numbers, 14pt labels below):
  - "34 points" / "Velocity"
  - "86%" / "Completion rate"
  - "0" / "Open blockers"
- Key sentence (16pt): "Sprint goal achieved: relational memory prototype delivered on schedule."
- Speaker notes: "We set a target of 32 to 35 points. We delivered 34. We completed 12 of 14 committed stories—86%—with two stories carrying over due to scope expansion, not team capacity. And critically, we had one mid-sprint blocker that we resolved in partnership with the platform team. Zero open blockers at end of sprint."

**SLIDE 3: Business Impact**
- Headline (32pt): "Phase 3 Unlocked"

  - "API partnership established; platform team committed to Q2 support"

- Speaker notes: "Here's what this means for the business. One: we can now run customer research on the relational memory feature—this was a gating item. We're tracking to start that research at month-end. Two: we didn't just ship an API; we established a partnership model with the platform team that will be the template for how we integrate future high-throughput features. Three: we hit a constraint—the API rate limit—but by working with the platform team, we solved it and established a pattern. That's de-risking Phase 3."

**SLIDE 4: What We Shipped**
- 3 feature blocks (columns, each with title + 1-sentence description + assignee):
  - "Relational Memory API" / "Core data model, versioning, encryption" / "Alice"
  - "Session Persistence" / "Browser storage layer with conflict resolution" / "Bob"
  - "Recovery Flow" / "User-facing undo and session restore UI" / "Carol"
- Speaker notes: "We shipped three major components. Alice owned the API design and implementation—that's the foundation everything else rests on. Bob built the browser persistence layer, which is trickier than it sounds because we had to handle conflict resolution when a user's session data diverges across devices. And Carol built the recovery flow, the user-facing moment when someone can restore a previous session. Together, these are the core of the prototype."

**SLIDE 5: Metrics Dashboard**
- [PLACEHOLDER: Velocity trend chart, 4 sprints, line graph, trending upward]
- [PLACEHOLDER: Completion rate gauge, 86%, visual gauge or bar]
- [PLACEHOLDER: Contributor breakdown, bar chart or table, 5 people listed with point contributions]
- Speaker notes: "Let me walk through three supporting metrics. First: velocity trend. We've been on an upward trajectory. Last sprint was 28 points, the one before that 31, and we just hit 34. That's a 21% improvement over the 3-sprint average. Why? The backend team allocation we added two sprints ago is paying dividends. Second: completion rate. We hit 86%. We target 90%, so we're slightly below, but that's because we made a deliberate scope expansion on the payment validation refactor, which we're carrying over. If we exclude carry-over decisions, we're at 94% completion on what we committed to complete. Third: team contribution. All five team members participated. Alice and Bob carried the heaviest load—12 and 8 points respectively—and that's by design; they led the big architectural pieces. But Dave and Carol and Eve all contributed meaningfully."

**SLIDE 6: Blockers & Risks**
- Blocker (resolved):
  - "API Rate Limit" / "Resolved mid-sprint" / "Mitigation: Platform team allocated dedicated quota"
- Risk (forward-looking):
  - "Payment Refactor Carry-Over" / "2 stories, 5 points" / "Mitigation: Prioritizing next sprint; low roadmap impact"
- Speaker notes: "We had one blocker mid-sprint. The backend API wasn't configured for the traffic profile we needed. We worked with the platform team, they allocated dedicated quota for our use case, and we moved forward. The learning here is that for high-throughput integrations, we should pre-allocate quota earlier in the design phase—that's a pattern for Phase 3. Looking ahead, we have two stories carrying over: the payment validation refactor. That's not a risk to the roadmap; it's independent of the Phase 1 merge. We'll prioritize it next sprint and complete it early."

**SLIDE 7: Capacity & Forecast**
- Target velocity (next sprint): 32–35 points (visual gauge or simple number)
- Roadmap alignment: "On track for Phase 1 completion by May 15"
- Forecast methodology: Show how this sprint's metrics inform next sprint's planning
- Speaker notes: "Based on this sprint, we're targeting 32 to 35 points for next sprint. We have two carry-over stories totaling 5 points, so we'll absorb those into the forecast, leaving room for 27 to 30 points of new work. We have one spike-week buffer for critical bugs or escalations, but the team is healthy and pacing well. This puts us on schedule for Phase 1 completion by mid-May."

**SLIDE 8: Q&A (script)**
- Anticipated questions + suggested answers:

  - Q: "What's the risk of carry-over affecting the roadmap?"

  - Q: "When do we start customer research?"

- Speaker notes: "I'll open it up to questions now. Here are three I anticipate, and my suggested answers. But the room may have other questions—I'll stay present and honest. If I don't know, I'll say so and follow up."
